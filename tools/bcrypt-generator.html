What is bcrypt?

bcrypt is a password hashing function designed for secure password storage. It incorporates a salt to protect against rainbow table attacks and a configurable cost factor that makes brute‑force attacks slower as hardware improves. It's widely used in web applications and is considered a best practice for storing user passwords.

This tool generates bcrypt hashes using the bcryptjs library (client‑side). The hash includes the algorithm version, cost factor, salt, and the actual hash. You can then verify passwords by comparing them against the stored hash (e.g., using bcrypt.compare in your backend).

All processing is done locally; your password never leaves your browser.

How to Use

Step 1: Enter a password in the input field.
Step 2: Select the cost factor (higher = more secure but slower).
Step 3: Click "Generate Hash". The bcrypt hash will appear.
Step 4: Copy the hash using the "Copy Hash" button.

Use the generated hash to store in your database. Later, to verify a login attempt, compare the provided password with the stored hash using bcrypt's compare function.

Pro Tips

  • Use a cost factor of at least 10 for production systems.
  • Never store plaintext passwords; always use bcrypt or similar.
  • bcrypt has a maximum input length of 72 bytes; longer passwords are truncated (this is a known limitation).
  • The hash output format is standardized: $2a$ (version), cost, salt, and hash.
  • Use the copy button to easily paste the hash into your code or database.

Frequently Asked Questions

What does the cost factor mean?
The cost factor determines how many iterations of the key derivation function are performed (2^cost rounds). Higher cost makes the hash slower to compute, increasing resistance to brute‑force attacks.
Is bcrypt still secure?
Yes, bcrypt remains a strong, widely‑accepted password hashing algorithm. For extremely high security, consider using Argon2id, but bcrypt is sufficient for most applications.
Can I use this hash in my application?
Yes, the output is a standard bcrypt hash that can be used with any bcrypt library (e.g., bcrypt on Node.js, Spring Security, Python's bcrypt).
Why does the hash change each time?
bcrypt automatically generates a random salt for each hash. This prevents pre‑computed rainbow table attacks.
Is my password sent to a server?
No, the hashing is done entirely in your browser using bcryptjs.
What about passwords longer than 72 characters?
bcrypt truncates to 72 characters. For longer passwords, consider pre‑hashing with SHA‑256 before bcrypt, but this is rarely needed.
